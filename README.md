# 🏥 WFM-Lite: Аналитика нагрузки колл-центра «Ясень»

Добро пожаловать в репозиторий проекта **WFM-Lite** (Workforce Management Lite). Этот репозиторий ведёт системный аналитик команды КлинПоток. 

Здесь собирается вся аналитическая документация, спецификации API, диаграммы и протоколы встреч по задаче выделения сервиса аналитики нагрузки колл-центра из монолита «КлинПоток.Регистратура».

> 💡 **Примечание:** Этот проект является частью учебной стажировки, но организован по стандартам реальной ИТ-компании. Репозиторий служит как рабочим пространством, так и элементом профессионального портфолио.

---

## 📌 О проекте

- **Заказчик:** Сеть клиник «Ясень» (12 клиник, единый колл-центр).
- **Проблема:** В часы пик пациенты не могут дозвониться, что приводит к жалобам и потере записей. Бизнесу нужна прозрачная аналитика нагрузки для своевременного реагирования.
- **Цель сервиса WFM-Lite:** Сбор, агрегация и визуализация метрик нагрузки колл-центра (звонки, чаты) для оптимизации работы операторов регистратуры.
- **Текущий статус:** 🟡 Неделя 0: Онбординг, изучение домена, настройка рабочего места, задача WFM-1.

---

## 👩‍💻 Моя роль

**Системный аналитик:** 
- Сбор и формализация требований от заказчика.
- Проектирование контрактов API (OpenAPI) и событий (AsyncAPI).
- Моделирование процессов (BPMN/UML) и описание текущей системы (As-Is) и целевой (To-Be).
- Сопровождение задачи до статуса Done (включая прохождение ревью у наставника).

---

## 🗂 Структура репозитория

Репозиторий организован по принципу *Docs-as-Code* (документация как код). 

```text
.
├── README.md              # Этот файл: общее описание и навигация
├── docs/                  # Основная документация
│   ├── glossary.md        # Глоссарий домена (термины колл-центра и медицины)
│   ├── meetings/          # Протоколы встреч (напр., 2026-11-18-zakazchik.md)
│   ├── as-is/             # Описание текущей системы (монолит)
│   ├── requirements/      # Требования к новым фичам (User Stories, функциональные требования)
│   ├── decisions.md       # ADR (Architecture Decision Records): журнал ключевых решений
│   └── questions.md       # Реестр открытых вопросов (кому задан, статус)
├── api/                   # Контракты: OpenAPI (REST) и AsyncAPI (Kafka)
├── diagrams/              # Исходники диаграмм (.puml, .mmd, .drawio)
├── sql/                   # SQL-запросы для анализа данных или создания схем
└── postman/               # Экспорт коллекций Postman для тестирования API
